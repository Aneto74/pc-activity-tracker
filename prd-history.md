## [2026-03-07] Сессия 4: Авто-выгрузка дня в Markdown

### Задача
Агент должен автоматически создавать дневной Markdown-отчёт в папке `D:\02 Area\Personal Base\Life\Activity\YYYYMMDD-activity.md`.
Пользователь также может перезаписать любой день вручную через дашборд.

### Дизайн решения

**Формат файла** — Markdown (`.md`), чтобы файлы читались в Obsidian и подавались в Claude Code как контекст.

**Имя файла:** `YYYYMMDD-activity.md` (уточнено в сессии 5)
**Путь:** настраивается в конфиге (`export_dir`), дефолт = `D:/02 Area/Personal Base/Life/Activity`

**Структура файла:**
```
# Активность — YYYY-MM-DD

Активно: Xч Yм  ·  Неактивен: Xч Yм  ·  Событий: N

---

## По категориям
| Категория | Время | % от активного |
...

---

## По приложениям
| Приложение | Категория | Время | % |
...

---

## По сайтам
| Приложение | Категория | Время | % |
...

> ⏸ Неактивен: Xч Yм (N% от всего времени)
```

**Триггеры генерации:**
1. **Автоматически при запуске агента** — проверяет, есть ли файл за вчерашний день. Если нет → создаёт.
2. **Ежедневно в 00:02 и 12:02** — фоновый поток будит себя по расписанию.
3. **Вручную через API** — `POST /export/day {"date": "YYYY-MM-DD"}`. Всегда перезаписывает.
4. **Кнопка «💾 Сохранить день в файл»** на вкладке Сегодня.
5. **Кнопка «💾 Перезаписать день»** на вкладке История (для выбранного дня).
6. **Кнопка «💾 Перезаписать период»** на вкладке История (для всего диапазона дат).

### Изменения по файлам

| Файл | Изменение |
|------|-----------|
| `agent/config.py` | Добавлен `export_dir` в `DEFAULTS` = `"D:/02 Area/Personal Base/Life/Activity"` |
| `agent/database.py` | `generate_daily_export(date_str, export_dir)`: строит Markdown, разделяет .exe и домены, обрабатывает нет-данных |
| `agent/api.py` | `POST /export/day` |
| `agent/main.py` | `_auto_export_loop()` — daemon thread, запуск при старте + 00:02 + 12:02 |
| `ui/index.html` | Кнопки «Сохранить в файл» + «Перезаписать день», `saveDayToFile()`, toast |

### Решения и обоснования

**Почему Markdown, а не JSON?**
Markdown читается напрямую в Obsidian (Personal Base) без конвертации. JSON-экспорт для Claude уже есть в `/export`. Markdown — для «дневника активности» в PARA-системе.

**Почему только вчерашний день автоматически, а не сегодня?**
Сегодня ещё не закончился — данные неполные. Вчерашний день уже завершён.

**Почему 12:02 дополнительно к 00:02?**
Если агент не запущен в полночь (пользователь выключал ПК), то при старте в середине дня файл всё равно создастся без ожидания следующей полуночи.

**Нет данных → нет файла:**
`generate_daily_export` возвращает `None` если `total_events == 0`. Файл не создаётся. API возвращает `{"ok": true, "skipped": true}`. Toast показывает «— Нет данных за {date}».

**Разделение «По приложениям» и «По сайтам»:**
`.exe`-файлы идут в отдельную секцию от веб-доменов. Внутренние адреса (`127.0.0.1`, `localhost`) исключаются полностью.

**Перезапись vs append:**
Всегда перезаписываем. Пользователь мог поменять категории → перезапись отразит актуальную классификацию.

**UX таблицы приложений:**

- После назначения категории через ✏️ показывается toast «✓ Категория сохранена»

### Ключевые технические детали

**Корневая причина проблемы с категориями:**
`insert_event()` вызывал `_classify()` в момент записи и сохранял `category_id`. `get_stats()` делал `LEFT JOIN categories c ON c.id = e.category_id` — то есть брал категорию из самого события. Изменение правил через UI не меняло уже записанные события.

**Выбранное решение:** Пересчёт при чтении. Альтернатива — `UPDATE events SET category_id=...` при сохранении категорий — сложнее и рискует потерять ручные назначения в будущем.

**Диагностика «две базы данных»:**
Отладочные скрипты обращались к `data/tracker.db`, агент использует `data/activity.db` (из конфига). Для диагностики нужно всегда запрашивать через `curl http://127.0.0.1:27420/...`, а не напрямую по пути к файлу.

**Важно:** после изменения `database.py` агент нужно **перезапустить** — Flask загружает модуль при старте, старый код остаётся в памяти до перезапуска.

### Решения и обоснования

**Idle detection:** `ctypes.windll.user32.GetLastInputInfo` — не требует прав администратора, работает на Windows без дополнительных пакетов.

**Web UI:** один HTML-файл без зависимостей — раздаётся Flask через `send_from_directory`. Dashboard, Категории, История, Экспорт и Настройки реализованы на Vanilla JS + Canvas API.

**Chrome Extension:** URL браузера подаётся двумя путями:
1. Extension → `POST /event` → напрямую пишет в БД как `source=extension`
2. Extension → `update_browser_state()` → следующий тик агента подхватывает URL для активного окна браузера

**Дедупликация:** при подсчёте статистики агентские события браузера пропускаются, если в ±15 сек есть событие от расширения (чтобы не считать одно и то же дважды).

**Категоризация:** происходит в момент записи события (`database._classify`). Правила применяются в порядке `sort_order` категории → `sort_order` правила. Первое совпадение побеждает. (В сессии 3 добавлен пересчёт на лету при чтении.)

### Проблемы и решения

**psutil не был в requirements.txt** — добавлен после тестирования импортов.

**Автозапуск (F-10)** не реализован. На Windows требует записи в реестр (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`) или создания задачи в планировщике. Отложено.

**Кириллица в терминале** — визуальный артефакт Windows-консоли, данные в SQLite хранятся корректно (UTF-8).
