# PC Activity Tracker — PRD

**Версия:** 1.3
**Дата:** 2026-03-09
**Платформа:** Windows
**Компоненты:** Desktop Agent (Python) + Chrome Extension + Web UI

---

## 1. Обзор продукта

PC Activity Tracker — легковесный локальный инструмент, который в фоновом режиме фиксирует активность пользователя за компьютером: активное приложение, заголовок окна, посещаемые сайты в Chrome. Все данные хранятся локально в SQLite. Настройка категорий и просмотр статистики доступны через браузерный HTML-интерфейс.

**Главный сценарий использования:** накопление структурированного контекста о рабочем дне, который затем экспортируется в Markdown (для Obsidian / PARA-системы) и в Claude Code для анализа продуктивности.

### Проблема

Коммерческие трекеры (RescueTime, Focus & Timesheets) стоят $10–15/мес. Нужен собственный инструмент без подписки, с полным контролем над данными и возможностью экспорта в AI-совместимые форматы.

### Критерии успеха

- Трекер работает незаметно в трее и не требует ручного запуска каждый день
- Пользователь может за 2 минуты настроить категории через UI и получить понятный дневной отчёт
- Ежедневные Markdown-файлы автоматически появляются в PARA-базе знаний (Obsidian)
- Экспорт в JSON/CSV готов к подаче в Claude Code без дополнительной обработки

## 2. Архитектура системы

Три компонента общаются через локальный HTTP-сервер на `localhost:27420`:

| Компонент | Технология | Роль |
|-----------|-----------|------|
| Desktop Agent | Python 3.10+ | Опрос активного окна каждые N секунд, запись в SQLite, HTTP API, системный трей, авто-экспорт Markdown + CSV |
| Chrome Extension | Manifest V3, JS | Перехват URL и заголовка активной вкладки, отправка на localhost API |
| Web UI | HTML + CSS + Vanilla JS | Настройка категорий, просмотр статистики, управление агентом, экспорт |

**Поток данных:**

```
Desktop Agent (опрос окна) ──→ SQLite ──→ HTTP API (localhost:27420)
Chrome Extension (URL + заголовок) ──→ HTTP API ──→ SQLite
Web UI ↔ HTTP API (статистика, категории, экспорт)
HTTP API ──→ Markdown файлы (D:/02 Area/Personal Base/Life/Activity/)
HTTP API ──→ CSV файлы     (D:/02 Area/Personal Base/Life/Activity/CSV/)
```

## 3. Desktop Agent

### 3.1 Сбор данных

Агент запускается при старте системы и работает в фоне. Каждые 10 секунд (настраивается) фиксирует:

- Имя активного приложения (process name через psutil)
- Заголовок активного окна (win32gui)
- Временную метку (Unix timestamp)
- Флаг idle — пользователь не активен более N минут

Реализация Windows: `win32gui.GetForegroundWindow()` + `psutil.Process(pid).name()`

### 3.2 Idle Detection

`ctypes.windll.user32.GetLastInputInfo` — не требует прав администратора. Если пользователь не активен более 5 минут (настраивается), событие помечается `is_idle=1` и не учитывается в рабочем времени.

### 3.3 Системный трей

`pystray`. Контекстное меню:
- Пауза / Возобновить трекинг
- Открыть Dashboard
- Статус: записано сегодня X событий
- Выход

### 3.4 HTTP API (localhost:27420)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/` | Web UI (index.html) |
| POST | `/event` | Принять событие от Chrome Extension `{url, title}` |
| GET | `/stats?date=YYYY-MM-DD` | Статистика за день: by_app, by_category, events, active/idle seconds |
| GET | `/categories` | Список категорий с правилами |
| POST | `/categories` | Сохранить полный список категорий (полная замена) |
| GET | `/config` | Текущая конфигурация |
| POST | `/config` | Обновить конфигурацию |
| GET | `/status` | Статус агента (running/paused, events_today) |
| POST | `/pause` | Приостановить запись |
| POST | `/resume` | Возобновить запись |
| GET | `/logs?n=100` | Последние N строк из `data/agent.log` |
| GET | `/export?from=&to=&format=json\|csv` | Экспорт данных за период |
| POST | `/export/day` | Записать/перезаписать Markdown-файл за один день `{date}` |
| POST | `/export/day-csv` | Записать/перезаписать CSV-файл за один день `{date}` |
| POST | `/export/range` | Записать/перезаписать Markdown-файлы за период `{from, to}` |
| GET | `/autostart` | Статус автозапуска Windows `{enabled: bool}` |
| POST | `/autostart` | Установить автозапуск Windows `{enabled: bool}` |

### 3.5 Авто-экспорт Markdown + CSV

Фоновый поток `_auto_export_loop` запускается вместе с агентом:

1. **При старте** — проверяет наличие файлов за вчерашний день. Если нет — создаёт.
2. **В 00:02** — создаёт файлы за вчерашний день (если ещё нет).
3. **В 12:02** — повторная проверка (на случай если агент не работал в полночь).

Каждый триггер создаёт **оба** файла: Markdown и CSV.

**Markdown:**
- Путь: `{export_dir}/YYYYMMDD-activity.md` (например `20260307-activity.md`)
- Дефолт export_dir: `D:/02 Area/Personal Base/Life/Activity`

**CSV:**
- Путь: `{export_dir}/CSV/activity_YYYY-MM-DD_YYYY-MM-DD.csv`
- Содержит все сырые события за день, пересчитанные по актуальным правилам
- Кодировка `utf-8-sig` (корректно открывается в Excel)
- Колонки: `datetime, app_name, window_title, url, page_title, category, is_idle, source`

## 4. Chrome Extension

### 4.1 Принцип работы

Расширение отслеживает смену активной вкладки и навигацию. При каждом изменении отправляет `POST /event {url, title}`. Расширение не хранит историю — только транслирует события.

### 4.2 Manifest V3 структура

- `background.js` (Service Worker): `chrome.tabs.onActivated`, `chrome.tabs.onUpdated`
- `popup.html` + `popup.js`: краткая статистика дня, ссылка на Dashboard
- Разрешения: `tabs`, `activeTab`, `host_permissions: ["http://127.0.0.1:27420/*"]`
- CSP: inline scripts запрещены в MV3 — логика вынесена в `popup.js`

### 4.3 Дедупликация с агентом

При подсчёте статистики агентские события браузера пропускаются, если в ±15 сек есть событие от расширения (`source=extension`). Это предотвращает двойной счёт одной и той же сессии.

### 4.4 Обработка приватного режима

URL из режима инкогнито не отслеживаются по умолчанию.

## 5. Web UI (HTML Dashboard)

Один HTML-файл без зависимостей — `ui/index.html`, раздаётся Flask. Реализован на Vanilla JS + Canvas API.

### 5.1 Вкладка: Сегодня

- **День-навигатор** `‹ Сегодня, Пн ›` — кнопки «предыдущий / следующий день». Переключает `viewDate`; кнопка «›» отключена для сегодняшнего дня. Формат: «Сегодня, Пн» или «Вт, 08.03.2026».
- **Круговая диаграмма** распределения времени по категориям (Canvas API)
- **Карточка Время:** активное время, idle время, количество событий + **разбивка по категориям** «Работа — 55% — 4ч 2м» для каждой категории
- **Кнопка «💾 Сохранить день в файл»** — записывает/перезаписывает Markdown за `viewDate`
- **Timeline:** горизонтальная шкала часов с блоками активности (цвет = категория); использует локальное время (не UTC)
- **Таблица приложений:** приложение → категория → время → % + кнопка ✏️
  - Кнопка ✏️ вызывает category picker (попап со списком категорий)
  - Для внутренних адресов (`127.0.0.1`, `localhost`) кнопка ✏️ скрыта
  - Строка «⏸ Неактивен N мин» внизу таблицы (серый цвет)
- **Toast-уведомления** — всплывающая тёмная плашка снизу экрана (после назначения категории, после сохранения файла)
- **Авто-обновление каждые 30 сек** — только если `viewDate === today()`

### 5.2 Вкладка: Категории

CRUD-редактор категорий и правил:

| Поле | Описание |
|------|----------|
| Название | Произвольное, например «Работа», «Учёба» |
| Цвет | HEX-цвет, используется в диаграммах и timeline |
| Тип правила | `app_contains` \| `url_contains` \| `app_exact` \| `url_domain` |
| Значение правила | Строка для сопоставления (без регулярок) |
| Порядок | Правила проверяются сверху вниз; первое совпавшее побеждает |
| По умолчанию | Применяется если ни одно правило не совпало |

**Предустановленные категории (6 шт., 18+ правил):**
- **Работа:** Slack, Zoom, Notion, Linear, VS Code, Figma, Word, Excel
- **Браузер (рабочий):** GitHub, Google Docs, linear.app
- **Коммуникации:** Telegram, WhatsApp, Outlook, Thunderbird
- **Учёба:** LingQ, Anki
- **Отдых:** YouTube, Netflix, VK
- **Прочее:** категория по умолчанию

**Category picker (попап):**
При нажатии ✏️ в таблице приложений открывается попап с выбором категории. Можно выбрать существующую или создать новую прямо в попапе. После выбора правило автоматически добавляется к категории.

### 5.3 Вкладка: История

- **Выбор периода** (от / до)
- **Бар-чарт по дням:** стэкированные бары, цвета = категории
- **Топ приложений за период:** агрегированная таблица
- **Кнопка «Показать»** — загружает и отрисовывает данные
- **Кнопка «💾 Перезаписать день»** — записывает Markdown-файл для даты «От»
- **Кнопка «📊 Сохранить CSV»** — записывает CSV-файл для даты «От» в `CSV/` подпапку; показывает путь к файлу в toast
- **Кнопка «💾 Перезаписать период»** — создаёт/перезаписывает Markdown-файлы для всех дней диапазона; показывает toast с `"Записано: N файлов, без данных: M"`

### 5.4 Вкладка: Экспорт

- Выбор периода и формата (JSON / CSV)
- JSON-формат оптимизирован для подачи в Claude Code: сводка по категориям, топ-приложения
- Кнопка «Сгенерировать промпт» — готовый промпт для Claude с вставленными данными
- Кнопка «Копировать промпт»

### 5.5 Вкладка: Настройки

- Интервал опроса (5 / 10 / 30 / 60 секунд)
- Порог idle (2 / 5 / 10 / 15 минут)
- Порт API (по умолчанию 27420)
- **Автозапуск при старте Windows** — toggle-переключатель. Читает/записывает реестр `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` через `GET /autostart` / `POST /autostart`

## 7. Нефункциональные требования

### 7.1 Производительность

- Потребление CPU агентом в фоне: < 0.5% (при интервале 10 сек)
- Потребление RAM: < 50 МБ
- Время отклика HTTP API: < 100 мс
- Web UI загружается за < 1 сек на localhost

### 7.2 Хранение данных

- SQLite WAL-mode — единственное хранилище, без внешних зависимостей
- `data/activity.db` — база событий (путь настраивается в конфиге)
- `data/config.json` — конфигурация агента
- `data/agent.log` — RotatingFileHandler 1 МБ × 2 файла
- Markdown-файлы: `{export_dir}/YYYYMMDD-activity.md`
- CSV-файлы: `{export_dir}/CSV/activity_YYYY-MM-DD_YYYY-MM-DD.csv`

### 7.3 Приватность и безопасность

- Всё работает локально, никакие данные не отправляются в сеть
- Порт 27420 слушает только на `127.0.0.1`
- Инкогнито-вкладки не трекируются без явного разрешения

### 7.4 Надёжность

- Все фоновые потоки — daemon threads (завершаются вместе с процессом)
- SQLite WAL-mode корректно обрабатывает параллельные запросы
- `generate_daily_export` возвращает `None` если нет данных — файл не создаётся

## 8. Схема данных SQLite

### Таблица `events`

```sql
CREATE TABLE events (
    id            INTEGER PRIMARY KEY,
    timestamp     INTEGER NOT NULL,       -- Unix timestamp
    app_name      TEXT NOT NULL,          -- имя процесса (напр. chrome.exe)
    window_title  TEXT,                   -- заголовок окна
    url           TEXT,                   -- URL из Chrome (NULL для не-браузерных)
    page_title    TEXT,                   -- заголовок страницы из Chrome
    category_id   INTEGER REFERENCES categories(id),
    is_idle       INTEGER DEFAULT 0,      -- 0/1
    source        TEXT DEFAULT 'agent'    -- 'agent' | 'extension'
);
CREATE INDEX idx_events_timestamp ON events(timestamp);
CREATE INDEX idx_events_app ON events(app_name);
```

### Таблица `categories`

```sql
CREATE TABLE categories (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL,
    color      TEXT NOT NULL,             -- HEX, например '#4A90E2'
    is_default INTEGER DEFAULT 0,         -- 0/1; одна категория по умолчанию
    sort_order INTEGER DEFAULT 0
);
```

### Таблица `rules`

```sql
CREATE TABLE rules (
    id          INTEGER PRIMARY KEY,
    category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    rule_type   TEXT NOT NULL,  -- app_contains | url_contains | app_exact | url_domain
    value       TEXT NOT NULL,
    sort_order  INTEGER DEFAULT 0
);
```

## 9. Формат Markdown-отчёта

Файл `YYYYMMDD-activity.md` в папке `export_dir`:

```markdown
# Активность — YYYY-MM-DD

**Активно:** Xч Yм  ·  **Неактивен:** Xч Yм  ·  **Событий:** N

---

## По категориям

| Категория | Время | % от активного |
|-----------|-------|----------------|
| Работа    | 4ч 2м | 48%            |
| ...       | ...   | ...            |

---

## По приложениям

| Приложение | Категория | Время | % |
|-----------|-----------|-------|---|
| code.exe  | Работа    | 2ч 1м | 24% |
| ...       | ...       | ...   | ...|

---

## По сайтам

| Приложение | Категория | Время | % |
|-----------|-----------|-------|---|
| github.com | Браузер (рабочий) | 1ч 5м | 13% |
| ...        | ...               | ...   | ...|

> ⏸ Неактивен: 1ч 15м (13% от всего времени)
```

**Правила формирования:**
- `.exe` файлы → секция «По приложениям»
- Веб-домены (содержат `.`, не заканчиваются на `.exe`) → секция «По сайтам»
- Внутренние адреса (`127.0.0.1`, `localhost`) → не включаются
- Секция не выводится, если нет данных для неё
- При нулевых данных за день файл не создаётся
